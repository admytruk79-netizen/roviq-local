The production screenshot showed a valid routed polyline and valid ETA/distance while the HUD simultaneously displayed “Could not calculate a drivable route.” This means the routing request succeeded and the failure occurred after route data was accepted. The active requestRoute() updated the route, drew it, populated ETA/distance, then called map.fitBounds() inside the same try path. Any camera/render exception therefore propagated to startNavigation() and replaced the successful instruction with a false routing failure. The fix is to treat routing/data success separately from noncritical camera animation, and never overwrite a valid route with an error caused by fit/follow presentation.
